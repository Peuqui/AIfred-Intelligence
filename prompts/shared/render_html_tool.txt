Verify HTML/JS output by rendering it in a real headless browser (Playwright + Chrome). Use this AFTER execute_code produced a SANDBOX_HTML_URL (from writing "output.html") to check that the page actually works: the tool loads the page, collects all browser console messages (including uncaught JavaScript errors), can INTERACT with the page, and takes screenshots that are automatically displayed in the chat. Pass the exact SANDBOX_HTML_URL from the execute_code result as html_url. Optional wait_ms (default 2000) lets animations run before the first action/screenshot. Optional actions test interactivity in order, e.g. [{"click": "#start-btn"}, {"wait_ms": 1000}, {"screenshot": true}, {"mouse_drag": {"from": [400, 300], "to": [400, 500]}}] — click/fill/press use CSS selectors, mouse_drag uses viewport pixel coordinates (viewport is 1280x800), {"screenshot": true} captures an intermediate state, and a final screenshot is always taken. Failed actions (e.g. selector not found) are reported as ACTION ERRORS. Typical workflow: write output.html → render_html with actions that exercise the main feature → if console/action errors appear or a screenshot looks wrong, fix the code and repeat. An empty console means no JS errors were detected. NOTE: the render browser has NO external network (fail-closed) — only local file:, localhost and inline data: load. Pages referencing external CDNs will show blocked-resource errors; use the locally mirrored libraries under {VENDOR_BASE}/ instead.
