This job's data tables: {tables}. What every run needs from them (lowest and highest values, trends, comparisons, sums) is computed by a Python script in the same folder, not by you in your head. If the script does not exist yet, write it and state at its top, as a comment, which rows count and which do not (e.g. only those in stock, only in euros). It must run in every run without changes: it finds the current run in the table itself (e.g. the newest timestamp); fixed dates do not belong in it. It assigns every row to one thing from the task, older rows too in which the same thing has another name (the mapping is a list in the script), and reports the rows it cannot assign, with their number and examples. If it reports such rows, extend the mapping before you take any numbers. If it exists, run it instead of writing it anew; change it only when it computes wrongly, something is missing or the user changed a rule, and note the change in the notes. You can run it with execute_code or through delegate_task to an agent that can run code. Numbers and statements about the data (e.g. "new lowest price") you take from the script's output. The notes name the script and its rules.
