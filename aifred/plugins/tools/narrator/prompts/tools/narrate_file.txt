Turn a whole text document in the documents folder into ONE audio file (MP3) using the local TTS voice-cloning engine — the spoken counterpart to translate_file.

PREFER THIS over reading the file and speaking it yourself: the file content is read, chunked at paragraph boundaries, synthesized and concatenated entirely server-side — it never passes through your context, and the result is a downloadable file instead of a chat reply.

Typical pipeline for meeting recordings: the transcript already lies in the workspace ('transcript-….txt') → translate_file to the target language → narrate_file on the translated file.

Give "filename" relative to the documents root, WITHOUT a 'documents/' prefix (e.g. 'meeting-DE.txt' or 'kommentare/notizen.md'); call list_files first if unsure. The output defaults to '<name>.mp3' in the same folder (phone-friendly; pass a '.wav' output_filename to skip the encode). Long documents take real time (roughly 5-10x the audio duration) — tell the user the job is running and that progress appears in the debug console.

MULTI-VOICE (audio-drama mode): to narrate an interview/dialog with a different voice per speaker, first call list_narrator_voices to learn the valid voice names of the effective engine (they differ per engine — never guess or reuse names from another engine; prefer '★'-prefixed cloned voices when the list has them). Then write ONE marked-up transcript via write_file where every speaker turn starts on its own line with '[LABEL]:' (labels are free, e.g. '[FRAGE]:' / '[ANTWORT]:' or '[S1]:'), and make ONE narrate_file call passing speaker_voices mapping each label to a voice name from the list. Never split the dialog into many files with one narrate_file call each. The markers are stripped before synthesis; text before the first marker uses the default voice. An unknown voice or a label without a mapping aborts with a clear error (no silent fallback). The markers survive translate_file, so a translated transcript can be narrated multi-voice too.

The result contains a ready-made "url". When sharing it in chat, ALWAYS use a Markdown link ([filename](url)) — it opens in a new tab where the browser's audio player plays the MP3. Never write raw <a> HTML; it renders as a dead link.
