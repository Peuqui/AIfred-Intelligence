Turn a whole text document from the documents folder into ONE audio file (MP3 by default) with the local voice-cloning TTS engine. PREFER THIS over reading the file and speaking it yourself: reading, chunking, synthesis and concatenation run server-side, the text never passes through your context, and the result is a downloadable file instead of a chat reply. Typical for meeting recordings: narrate the transcript in the workspace ('transcript-….txt') or a translated copy of it. Long documents take real time (roughly 5-10x the audio duration): tell the user the job is running and that progress appears in the debug console.

MULTI-VOICE (audio drama, interview, dialog): call list_narrator_voices first. Write ONE marked-up transcript file in which every speaker turn starts on its own line with '[LABEL]:' (free labels, e.g. '[FRAGE]:' / '[ANTWORT]:' or '[S1]:'), then make ONE narrate_file call with speaker_voices mapping every label to a voice. Never split the dialog into many files with one call each. An unknown voice or an unmapped label aborts with an error. The markers survive a translation, so a translated transcript can be narrated multi-voice too.

The result contains a ready-made "url": share it ONLY as a Markdown link ([filename](url)), which opens the browser's audio player in a new tab — raw <a> HTML renders as a dead link.
