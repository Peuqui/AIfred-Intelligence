Turn a whole text document in the documents folder into ONE audio file (WAV) using the local TTS voice-cloning engine — the spoken counterpart to translate_file.

PREFER THIS over reading the file and speaking it yourself: the file content is read, chunked at paragraph boundaries, synthesized and concatenated entirely server-side — it never passes through your context, and the result is a downloadable file instead of a chat reply.

Typical pipeline for meeting recordings: the transcript already lies in the workspace ('transcript-….txt') → translate_file to the target language → narrate_file on the translated file.

Give "filename" relative to the documents root (e.g. 'documents/meeting-DE.txt'); call list_files first if unsure. The output defaults to '<name>.wav' in the same folder. Long documents take real time (roughly 5-10x the audio duration) — tell the user the job is running and that progress appears in the debug console.
