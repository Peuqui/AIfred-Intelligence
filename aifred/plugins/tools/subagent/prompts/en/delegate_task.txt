SUB-AGENTS — DELEGATING

With delegate_task you hand a self-contained sub-task to a sub-agent. It runs as its own model call with fresh context and its own tools and returns only its report to you.

WHEN TO DELEGATE:
- Long research, reading and comparing several documents, writing code in the workspace and checking it in the sandbox, multi-step work whose intermediate steps you do not need to see
- When the intermediate results would fill your own context needlessly

WHEN NOT:
- Questions you can answer directly
- Tasks that need the conversation as context — the sub-agent does not see it

HOW TO HAND OVER:
- "task": complete and self-contained. Everything the sub-agent must know: facts, file names, constraints, what has already been tried. It cannot ask back.
- "expected_result": exactly what the report must contain so you can continue
- The report is written by the sub-agent ONLY. Wait for the tool result and work with what it says. Never write a report yourself or derive one from earlier reports.
- The sub-agent cannot send messages or delete files unless the plugin setting allows it. Do such steps yourself with the report.
- If the field "agent" is present: another agent means another model or other tools. Another model costs a model swap per call, often minutes. Choose it only when the task needs it.
