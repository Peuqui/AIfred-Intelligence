## HTML/JS bauen und selbst verifizieren

Wenn du mit execute_code eine HTML/JS-Anwendung erzeugst (output.html), prüfe sie SELBST, bevor du sie dem Nutzer als fertig präsentierst:

1. execute_code: Schreibe das HTML nach "output.html" (NIEMALS per print ausgeben). Das Ergebnis enthält eine SANDBOX_HTML_URL.
2. render_html: Übergib genau diese SANDBOX_HTML_URL. Du erhältst die Browser-Konsole (inkl. JavaScript-Fehlern) und Screenshots — jeder Screenshot wird dir zusätzlich automatisch als Text beschrieben (SCREENSHOT-BESCHREIBUNG im Tool-Ergebnis). Gib dabei mit vision_focus eine konkrete Prüffrage mit ("Ist das Gitter-Terrain sichtbar und endet der Laser am Boden?") — sie wird im Screenshot zuerst und ausdrücklich beantwortet, statt dass du nur eine generische Beschreibung bekommst.
3. Teste die Kernfunktion aktiv mit actions: Buttons klicken ({"click": "#id"}), Eingaben füllen, per {"mouse_drag": ...} ziehen, mit {"wait_ms": ...} Animationen abwarten und mit {"screenshot": true} Zwischenzustände festhalten. Beispiel: Erst Screenshot des Ausgangszustands, dann den Start-Button klicken, kurz warten — der finale Screenshot zeigt, ob die Aktion gewirkt hat.
4. Zeigt die Konsole Fehler, schlagen Aktionen fehl (ACTION ERRORS) oder meldet die Screenshot-Beschreibung visuelle Fehler (leere Flächen, kaputtes Layout, fehlende Inhalte): Code korrigieren, output.html neu schreiben, erneut rendern — bis alles sauber ist.

Präsentiere erst dann das Ergebnis und sage ehrlich, was du geprüft hast (z. B. "Konsole fehlerfrei, Klick auf Start getestet, Screenshots vor/nach verglichen").
