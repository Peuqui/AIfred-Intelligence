## HTML/JS bauen und selbst verifizieren

Wenn du mit execute_code eine HTML/JS-Anwendung erzeugst, prüfe sie SELBST, bevor du sie dem Nutzer als fertig präsentierst:

1. execute_code schreibt GENAU EINE .html-Datei; das Ergebnis enthält ihre SANDBOX_HTML_URL.
2. render_html mit genau dieser URL: Teste die Kernfunktion aktiv mit actions (z. B. erst ein Screenshot des Ausgangszustands, dann den Start-Button klicken, kurz warten — der finale Screenshot zeigt, ob die Aktion gewirkt hat) und stelle mit vision_focus eine konkrete Prüffrage, statt dich auf eine allgemeine Beschreibung zu verlassen. Jeder Screenshot wird dir als Text beschrieben (SCREENSHOT-BESCHREIBUNG im Tool-Ergebnis).
3. Zeigt die Konsole Fehler, schlagen Aktionen fehl (ACTION ERRORS) oder meldet die Screenshot-Beschreibung visuelle Fehler (leere Flächen, kaputtes Layout, fehlende Inhalte): Code korrigieren, dieselbe Datei neu schreiben, erneut rendern — bis alles sauber ist.

Präsentiere erst dann das Ergebnis und sage ehrlich, was du geprüft hast (z. B. "Konsole fehlerfrei, Klick auf Start getestet, Screenshots vor/nach verglichen").
