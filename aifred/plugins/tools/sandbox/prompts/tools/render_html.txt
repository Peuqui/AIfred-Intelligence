Verify HTML/JS output by rendering it in a real headless browser (Playwright + Chrome). html_url accepts TWO sources: a SANDBOX_HTML_URL from a previous execute_code call in this session, OR a file in the user's documents workspace as "/_upload/documents/<path>.html" (subfolders allowed) — so a deliverable saved to documents/ can be rendered and verified DIRECTLY, no copying into the sandbox needed. The tool checks that the page actually works: the tool loads the page, collects all browser console messages (including uncaught JavaScript errors), can INTERACT with the page, and takes screenshots that are automatically displayed in the chat. Pass the exact SANDBOX_HTML_URL from the execute_code result as html_url. Optional wait_ms (default 2000) lets animations run before the first action/screenshot. Optional actions test interactivity in order, e.g. [{"click": "#start-btn"}, {"wait_ms": 1000}, {"screenshot": true}, {"mouse_drag": {"from": [400, 300], "to": [400, 500]}}] — click/fill/press use CSS selectors, mouse_drag uses viewport pixel coordinates (viewport is 1280x800), {"screenshot": true} captures an intermediate state, and a final screenshot is always taken. Failed actions (e.g. selector not found) are reported as ACTION ERRORS. Optional vision_focus: a specific verification question for the automatic screenshot description (e.g. "Does the ship cast a shadow on the terrain?") — the vision model answers it first; pass it whenever you render to verify a specific change instead of relying on a generic description. Typical workflow: write output.html (or save the deliverable to documents/) → render_html with actions that exercise the main feature and a vision_focus for what to verify → if console/action errors appear or a screenshot looks wrong, fix and repeat. For documents/ files, fix means: targeted patch_file edits (unique old excerpt → corrected excerpt) and render the SAME documents URL again — NEVER regenerate the whole file from memory. An empty console means no JS errors were detected. NOTE: the render browser has NO external network (fail-closed) — only local file:, localhost and inline data: load. Pages referencing external CDNs will show blocked-resource errors; use the locally mirrored libraries under {VENDOR_BASE}/ instead.
