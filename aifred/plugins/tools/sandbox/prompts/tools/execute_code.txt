Run Python in an isolated sandbox: calculations, statistics, data processing, simulations, file generation, plots — whenever real computation beats estimating. Libraries: {AVAILABLE_LIBRARIES} (nothing else can be installed, no network). 30-second time limit.

OUTPUT:
- print() everything you want back.
- Static plots: matplotlib (captured automatically). Interactive plots: plotly, saved with fig.write_html("<name>.html", include_plotlyjs=True).
- HTML/JS apps: write ONE .html file with a meaningful name (e.g. "fibonacci.html"); every .html file is picked up, so never save the same page under a second name. NEVER print HTML to STDOUT — printed HTML is dropped.
- Canvas and visualizations fill the view: width:100%, height:100vh, body margin and padding 0, no fixed pixel sizes.
- The render browser has no external network, CDNs fail silently. Use the local copies: Chart.js "{VENDOR_BASE}/chart.umd.min.js", D3 "{VENDOR_BASE}/d3.min.js", Plotly "{VENDOR_BASE}/plotly.min.js", Three.js "{VENDOR_BASE}/three.min.js". A library missing there: ask the user to add it (scripts/fetch_vendor_libs.sh), never use a CDN.
- Plots and HTML appear in the chat automatically: never show them again yourself (no base64, data URIs or img tags), just describe the result.

FILES: The user's documents are under the relative path "documents/" (e.g. open("documents/Polizei/foo.txt")), READ-ONLY here. Scratch files go into the current directory. The working directory is DELETED after each run: a later call cannot read files from an earlier one, and the copies embedded in the chat are invisible to all file tools. Anything you, another agent or the user needs later must be saved with execute_code_write to documents/<descriptive-name>, the only persistent, shared place. documents/ files are changed with a targeted patch, never regenerated from memory; a documents/ page is rendered directly with render_html ("/_upload/documents/<name>.html"), never copied into the sandbox to test it.
