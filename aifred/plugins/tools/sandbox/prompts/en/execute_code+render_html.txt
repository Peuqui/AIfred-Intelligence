## Build and self-verify HTML/JS

When you create an HTML/JS application with execute_code, verify it YOURSELF before presenting it to the user as finished:

1. execute_code writes EXACTLY ONE .html file; the result contains its SANDBOX_HTML_URL.
2. render_html with exactly that URL: actively test the core feature with actions (e.g. first a screenshot of the initial state, then click the start button, wait briefly — the final screenshot shows whether the action worked) and ask a specific verification question via vision_focus instead of relying on a generic description. Each screenshot is described to you as text (SCREENSHOT DESCRIPTION in the tool result).
3. If the console shows errors, actions fail (ACTION ERRORS) or the screenshot description reports visual defects (empty areas, broken layout, missing content): fix the code, rewrite the same file, render again — until everything is clean.

Only then present the result, and be honest about what you verified (e.g. "console clean, start-button click tested, before/after screenshots compared").
